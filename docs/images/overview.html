Briefing Desk: components

How an answer is made. Code fetches, computes and decides access. The model writes from cleared evidence, and a second check (code, then an LLM judge) verifies every claim.

Code Storage Access control boundary LLM
Sources

Client data

13 tables (CRM, revenue, holdings) and 31 documents (emails, notes, news).

Ingestion

Unify and check

Merge duplicates, match names, link documents, screen text, run quality checks.

Store

One database

Clean tables plus a keyword and meaning search index.

Access

Typed tools

The only way to read data. Coverage and clearance checked before anything returns.

Evidence

Evidence pack

Facts and passages, numbered E1, E2... Figures computed by code.

LLM

Writer

Writes each claim citing evidence IDs. Never computes a number.

Code + LLM

Checker and judge

Code: IDs exist, numbers match, quotes found. LLM judge: does the source support it?

Banker

Cited answer

Each claim Verified or Check sources, one click from its source.

Evaluation harness

Tests every layer before release: unit tests, 14 data traps, golden answers graded by a separate model, and a leak sweep across every user and client.
